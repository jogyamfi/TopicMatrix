# TopicMatrix

Spaced-repetition study tracker. See [documents/planning/requirements.md](documents/planning/requirements.md)
(SRS) and [documents/planning/delivery-plan.md](documents/planning/delivery-plan.md) (phased plan)
for the full spec.

## Quickstart (T1: Node + SQLite, no Docker, no Cloudflare account)

```bash
git clone <repo-url>
cd TopicMatrix
npm install
cp .env.example .env
npm run db:migrate
npm run seed:admin
npm run dev
```

This starts the Vite dev server (`http://localhost:5173`) and the Node API (`http://localhost:3000`)
concurrently. Vite proxies `/api/*` to the Node API, so the browser sees one origin.

## Switching to PostgreSQL

```bash
docker compose -f docker-compose.dev.yml up -d   # starts ONLY PostgreSQL
```

Then set in `.env`:

```
DATABASE_PROVIDER=postgresql
DATABASE_URL=postgresql://topicmatrix:topicmatrix@localhost:5432/topicmatrix
```

```bash
npm run db:migrate
npm run dev:pg
```

No code changes are required to switch providers — only `.env` + `npm run db:migrate`.

## Workspace layout

```
apps/
  web/          React SPA (Vite)
  api/          Node entrypoint — @hono/node-server. The ONLY place Node built-ins are allowed
  worker/       Cloudflare Workers entrypoint — exports { fetch } (optional deployment target)
packages/
  core/         Pure domain logic (scoring, scheduling) — lands at P3
  db/           Prisma schemas, generated clients, adapters, repositories
  api-core/     Hono app: routes, middleware, services. Runtime-agnostic
  shared/       Zod schemas, shared types, error codes, config/date helpers
prisma/
  model.prisma            shared model fragment (single source of truth)
  schema.sqlite.prisma     } generated by scripts/generate-schemas.ts —
  schema.postgres.prisma   } do not edit by hand, and do not commit
  schema.d1.prisma         } (gitignored)
documents/planning/        SRS, delivery plan, ADRs, phase handover notes
```

## Scripts

| Command | Purpose |
|---|---|
| `npm run dev` | Vite + Node API, SQLite (T1 baseline) |
| `npm run dev:pg` | Same, against PostgreSQL |
| `npm run dev:cf` | Run the Worker entrypoint locally via `wrangler dev` (optional; needs Cloudflare tooling) |
| `npm run db:migrate` / `db:reset` / `db:studio` | Respect `DATABASE_PROVIDER` from `.env` |
| `npm run seed:admin` | One-time initial admin user (Node only; refuses to run if any user exists) |
| `npm run build` | Builds all workspaces, including both API entrypoints |
| `npm run lint` / `typecheck` / `test` | Must all pass with zero warnings before merging |
| `npm run test:cf` | Cloudflare-Workers-runtime tests (needs `wrangler`/`workerd`; never required for T1) |

## Cloudflare Workers target (optional)

`wrangler` and related Cloudflare tooling are dev dependencies only. Nothing above requires a
Cloudflare account. See [documents/planning/adr-001-data-access.md](documents/planning/adr-001-data-access.md)
for the D1 data-access decision (Prisma + `@prisma/adapter-d1`, with a documented caveat about D1
having no real transaction support).

## Conventions

- TypeScript `strict: true`; no `any`; no unexplained non-null assertions.
- Node built-ins (`fs`, `path`, `crypto`, `process`, etc.) may only be imported in `apps/api/**` —
  enforced by an ESLint rule so the rest of the codebase stays portable to `workerd` (NF-13).
- No module-level singletons holding config/connections — `AppDeps` is rebuilt per request in both
  entrypoints (NF-15).
- Zod schemas in `packages/shared` are the single source of truth for request/response shapes.
